# Участник 3: оценка чатов и подготовка LoRA

## 1. Запустить рабочую оценку через Gemini

Адаптер `ai.gemini.GeminiEvaluator` принимает диалог и **текущую версию** чек-листа от backend, просит Gemini вернуть JSON, затем проверяет каждый ответ и точность цитат. Балл вычисляет backend. Выбрана `gemini-3.5-flash-lite` с `thinkingLevel=medium`: в AI Studio нашего бесплатного проекта подтверждены 15 RPM, 250 000 TPM и 500 RPD. Подробности проверки качества, остатка квоты и времени — в [ai-provider-check.md](ai-provider-check.md).

По умолчанию выполняется не более двух обращений к этой же модели, по 40 секунд каждое. Невалидная оценка повторяется с сообщением об ошибке и исходной репликой для исправления цитаты. Резервная Flash-модель выключена: её 20 RPD недостаточно. При явном задании `CQA_GEMINI_FALLBACK_MODEL` сохраняется прежний режим: основная попытка 15 секунд и две резервные по 40. Фактически ответившая модель и все обращения отражаются в метаданных. [Flash Lite](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite) поддерживает структурированный JSON и thinking.

Для стандартного критерия consultation отсутствие официального справочника явно отмечается `needs_review=true`; оценка полноты по тексту не подтверждает продуктовые факты. Для management в звонках так же указывается ограничение «только транскрипт, без аудио». Пропуск обязательной отметки отклоняется адаптером. Эти отметки не меняют балл и не заменяют N/A.

1. Создать API-ключ в [Google AI Studio](https://aistudio.google.com/apikey).
2. Скопировать `.env.example` в `.env` и вписать `GEMINI_API_KEY=...` **только в локальный файл**.
3. Запустить из корня репозитория:

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn ai.app:app --env-file .env --host 127.0.0.1 --port 8000
   ```

4. Открыть <http://127.0.0.1:8000/docs>. `/health` должен вернуть `ai_configured: true`. Импортировать синтетический набор через `scripts/import_dataset.py examples/synthetic-dataset.json`, затем вызвать `POST /api/v1/evaluations` с внутренним `conversation_id` из списка диалогов, `checklist_id: "freedom-broker"`, `checklist_version: 1`.

Для сервера с frontend, очередью и резервными копиями используйте hosted-фабрику:

```text
python -m uvicorn ai.app:create_hosted_app --factory
```

Ей нужны те же `CQA_*` переменные и `CQA_FRONTEND_PATH`, что и
`backend.hosting:create_hosted_app`. Ключ Gemini читается из окружения при
создании приложения; публичный сервер остаётся без AI, пока ключ там не настроен.

Настоящие DEV-диалоги не включены в Git. Команда разрешила их обработку в Gemini API с учётом [условий free tier](https://ai.google.dev/gemini-api/docs/pricing). В локальном `.env` и `.env.example` включено `CQA_GEMINI_ALLOW_VOICE_CALLS=1`, чтобы обработать все пять звонков. Отправляется только транскрипт, аудио не скачивается; ограничения проверки без аудио указываются в ответе. При отсутствии этой переменной сам адаптер по-прежнему закрывает обработку звонков.

Если ключ случайно раскрыт, удалите его в AI Studio и создайте новый. `.env` и `data/` игнорируются Git; `python -m scripts.check_secrets` проверяет отслеживаемые файлы, локальный pre-commit hook проверяет staged-файлы, CI повторяет проверку после push. Это защита от случайного коммита, поэтому права доступа и лимиты ключа всё равно настраиваются в Google Cloud/AI Studio.

Если ключа нет, backend продолжает поддерживать импорт и ручные оценки. Ответы модели, которые нарушают схему, шкалу или содержат вымышленную цитату, не сохраняются как успешная оценка.

## 2. Сделать эталонную разметку

`invoke.json` содержит диалоги, но не правильные ответы по критериям. Без ручной разметки LoRA не узнает, какую оценку считать верной.

```powershell
.\.venv\Scripts\python.exe -m ai.labels prepare "C:\Users\erken\Downloads\Doomsday\invoke.json" --per-language 10
```

Команда создаёт 30 черновиков: по 10 чатов RU/KZ/EN, в `data/labels/drafts/`. Файлы остаются локально; `data/` исключён из Git. Нумерация `m1`, `m2` и т. д. даёт точные ссылки на реплики. В каждом файле заполняйте `result.answers` для всех восьми критериев: `value`, короткое `explanation`, `evidence_kind` и **дословную** `quote` с верным `message_id`. Для `na` нужен `na_reason`; для `needs_review=true` нужен `limitation`. Для шкалы указывайте число, не строку. Флаг `gross: yes` означает нарушение.

Первые 30 чатов — пилот. Сверяйте спорные случаи с чек-листом и вторым участником команды. Затем можно подготовить остальные чаты в отдельной папке (`--per-language 20 --out ...`) и разметить их. Сохраните часть размеченных примеров для независимой проверки; команда `build` автоматически откладывает каждый пятый чат каждого языка.

После заполнения и проверки каждого черновика человеком установите
`"annotation_status": "reviewed"`, затем выполните:

```powershell
.\.venv\Scripts\python.exe -m ai.labels build
```

Скрипт проверит формат, значения и точные цитаты. Только при полной валидности он создаст `data/labels/sft/train.jsonl` и `validation.jsonl` в формате conversational prompt/completion для [TRL SFTTrainer](https://huggingface.co/docs/trl/sft_trainer). Эти файлы тоже содержат тексты диалогов и не должны попадать в Git или публичный Hugging Face Hub.

В этой рабочей копии есть отдельные 15 предварительно размеченных чатов в
`data/labels/seed-drafts/`. Они имеют `annotation_status: "provisional"` и не являются
экспертным эталоном. Для пробного локального обучения их можно собрать явно:

```powershell
.\.venv\Scripts\python.exe -m ai.labels build --drafts data/labels/seed-drafts --out data/labels/seed-sft --allow-provisional
```

Получится 12 примеров для обучения и 3 для проверки. Для оценки качества
потребуется независимая экспертная проверка меток и более широкий набор.
Для просмотра этих предварительных оценок есть локальная таблица
`data/labels/seed-summary.csv`: ID, язык, все восемь ответов, итог и критерии с
`needs_review`. Ещё один предварительно размеченный звонок лежит отдельно в
`data/labels/voice-draft/`; он не входил в первый пробный запуск обучения.
При проверке звонка учитывайте возможные ошибки транскрипции, а не приписывайте
их оператору. После ручного просмотра исправьте спорные ответы и только тогда
поменяйте `annotation_status` на `reviewed` для проверенных файлов.

Для отдельного быстрого замера на отложенных RU/KZ/EN чатах:

```powershell
.\.venv-dev\Scripts\python.exe -m ai.benchmark_gemini --allow-provisional
```

Локальный отчёт — `data/labels/gemini-benchmark.json`, он не публикуется. Актуальный расширенный прогон и сравнение конфигураций описаны в [ai-provider-check.md](ai-provider-check.md). Предварительные метки позволяют находить расхождения, но не заменяют экспертный эталон.

## 3. Экспериментальное локальное обучение LoRA

Для LoRA используется открытая `Qwen/Qwen3-0.6B`; Gemini остаётся отдельным API-провайдером. Для RTX 3050 с 6 ГБ памяти подготовлен формат «один критерий на пример»: 384 обучающих примера из 48 чатов и 96 проверочных из 12 чатов. Метки предварительные. Бэкенд может собрать восемь ответов через экспериментальный `LocalLoRAEvaluator`.

Установка CUDA, закреплённые версии ML-зависимостей, команды обучения, проверка генераций и запуск локального API описаны в [ai-lora.md](ai-lora.md). Скрипт следует [PEFT Quicktour](https://huggingface.co/docs/peft/quicktour), сохраняет отдельный адаптер и манифест с хешами данных и ошибкой до и после обучения. Данные и веса остаются в игнорируемой Git папке `data/`.
