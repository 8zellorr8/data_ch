# Участник 3: оценка чатов и подготовка LoRA

## 1. Запустить рабочую оценку через Gemini

Каждый сетевой вызов теперь проходит лимитер `CQA_GEMINI_RPM` (по умолчанию 3).
При HTTP 429 адаптер не повторяет запрос и не переключается на fallback:
backend сохраняет cooldown, возвращает Retry-After и откладывает безопасный
элемент пакета. Подробности: [частота, квоты и resume](backend-operations.md#10-частота-запросов-429-и-продолжение-пакета).
Указанные ниже 95/80 секунд ограничивают только сетевые ожидания: дополнительно
возможно ожидание разрешения лимитера, всё внутри общего тайм-аута backend 180 с.

Адаптер `ai.gemini.GeminiEvaluator` принимает диалог и **текущую версию** чек-листа от backend, просит Gemini вернуть JSON, затем проверяет каждый ответ и точность цитат. Балл вычисляет backend. По умолчанию сначала используется `gemini-3.8-flash` с `thinkingLevel=low`; при тайм-ауте или временной недоступности он переключается на `gemini-3.6-flash`. У первой модели лимит ожидания 15 секунд, у резервной 40 секунд; временный сбой резервной модели вызывает ещё одну попытку. Суммарный предел сетевого ожидания — 95 секунд, плюс небольшое время на проверку ответа. Реально ответившая модель и число вызовов сохраняются в метаданных оценки. `medium` можно выбрать после сравнения качества. [Gemini 3.8 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash) поддерживает структурированный JSON и уровни thinking.

В локальной проверке 3.8 Flash не ответил за 120 секунд. 3.6 Flash обычно отвечал за 6–8 секунд, но в последнем замере три DEV-чата заняли 22.62, 14.1 и 50.1 секунды. Поэтому для локального запуска установлено `CQA_GEMINI_MODEL=gemini-3.6-flash` в игнорируемом Git файле `.env`. Для прямого вызова 3.6 Flash максимальное сетевое ожидание двух попыток — 80 секунд. Если такой же выбор модели нужен на сервере, задайте эту переменную в его секретной конфигурации. Ответы и задержка могут различаться при повторных запросах.

1. Создать API-ключ в [Google AI Studio](https://aistudio.google.com/apikey).
2. Скопировать `.env.example` в `.env` и вписать `GEMINI_API_KEY=...` **только в локальный файл**.
3. Запустить из корня репозитория:

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn ai.app:app --env-file .env --host 127.0.0.1 --port 8000
   ```

4. Открыть <http://127.0.0.1:8000/docs>. `/health` должен вернуть `ai_configured: true`. Импортировать синтетический набор через `scripts/import_dataset.py examples/synthetic-dataset.json`, затем вызвать `POST /api/v1/evaluations` с внутренним `conversation_id` из списка диалогов, `checklist_id: "freedom-broker"`, `checklist_version: 1`.

Для сервера с frontend, очередью и резервными копиями используйте hosted-фабрику:

```text
python -m uvicorn ai.app:create_hosted_app --factory
```

Ей нужны те же `CQA_*` переменные и `CQA_FRONTEND_PATH`, что и
`backend.hosting:create_hosted_app`. Ключ Gemini читается из окружения при
создании приложения. На текущем alwaysdata ключ настроен; при проверке 7 ноября
2026 Google отказал из-за суточной квоты. [Фактическое состояние](ai-readiness.md).

Настоящие DEV-диалоги не включены в Git. Не отправляйте их в бесплатный облачный API, пока команда не согласовала обработку данных: [условия free tier](https://ai.google.dev/gemini-api/docs/pricing) предусматривают использование контента для улучшения продуктов. Звонки дополнительно закрыты настройкой `CQA_GEMINI_ALLOW_VOICE_CALLS=0`; даже при разрешении отправляется только транскрипт, не аудио. Бесплатный тариф и лимиты зависят от проекта; проверить их можно в AI Studio.

Если ключ случайно раскрыт, удалите его в AI Studio и создайте новый. `.env` и `data/` игнорируются Git; `python -m scripts.check_secrets` проверяет отслеживаемые файлы, локальный pre-commit hook проверяет staged-файлы, CI повторяет проверку после push. Это защита от случайного коммита, поэтому права доступа и лимиты ключа всё равно настраиваются в Google Cloud/AI Studio.

Если ключа нет, backend продолжает поддерживать импорт и ручные оценки. Ответы модели, которые нарушают схему, шкалу или содержат вымышленную цитату, не сохраняются как успешная оценка.

### Проверка объединённой версии

Проверка наличия конфигурации без сетевого запроса:

```text
python -m ai.check_connection --env-file .env
```

Проверка настоящего API на одном синтетическом диалоге, без DEV, БД и сохранения
ответа модели (запрос может расходовать квоту/оплачиваться):

```text
python -m ai.check_connection --env-file .env --live
```

Команда выводит модель, число обращений и результат проверки контракта, но не ключ,
транскрипт или полный ответ провайдера. `ai_configured=true` само по себе означает
только наличие ключа, а не успешный вызов. Коды завершения: 0 — проверка прошла,
1 — ошибка настоящего обращения, 2 — ключ отсутствует или настройки недопустимы.

Если возвращается HTTP 429, проверьте активные лимиты проекта в AI Studio.
Суточный лимит не исправляется немедленными повторами. Во время интеграции Google
указал для этого проекта 20 запросов Gemini 3.6 Flash в сутки и исчерпанную квоту.
Перед контрольным часом проверьте остаток с учётом 10 PROD и возможных повторов;
полный DEV из 65 разговоров не помещается в такой суточный лимит.
Не меняйте модель без проверки доступности и повторного сравнения качества.
[Официальные сведения о квотах](https://ai.google.dev/gemini-api/docs/rate-limits).

Расход остаётся `complete=false`. Если были обращения к разным моделям, токены
в агрегированном `ProviderUsage` остаются `null`: текущий контракт имеет только
одно поле тарифа и не позволяет честно оценить смешанный расход. Число всех вызовов
сохраняется, `model` указывает последнюю/успешную модель; неизвестный расход не ноль.
При повторах на одной модели учитываются известные токены всех попыток.

В Docker пакет `ai` включён в образ; ключ задаётся в `.env.docker`, а не в Dockerfile.
Промпт и оценки DEV не изменялись при интеграции. Состояние проверки и ограничения:
[ai-readiness.md](ai-readiness.md).

## 2. Сделать эталонную разметку

`invoke.json` содержит диалоги, но не правильные ответы по критериям. Без ручной разметки LoRA не узнает, какую оценку считать верной.

```powershell
.\.venv\Scripts\python.exe -m ai.labels prepare "C:\Users\erken\Downloads\Doomsday\invoke.json" --per-language 10
```

Команда создаёт 30 черновиков: по 10 чатов RU/KZ/EN, в `data/labels/drafts/`. Файлы остаются локально; `data/` исключён из Git. Нумерация `m1`, `m2` и т. д. даёт точные ссылки на реплики. В каждом файле заполняйте `result.answers` для всех восьми критериев: `value`, короткое `explanation`, `evidence_kind` и **дословную** `quote` с верным `message_id`. Для `na` нужен `na_reason`; для `needs_review=true` нужен `limitation`. Для шкалы указывайте число, не строку. Флаг `gross: yes` означает нарушение.

Первые 30 чатов — пилот. Сверяйте спорные случаи с чек-листом и вторым участником команды. Затем можно подготовить остальные чаты в отдельной папке (`--per-language 20 --out ...`) и разметить их. Сохраните часть размеченных примеров для независимой проверки; команда `build` автоматически откладывает каждый пятый чат каждого языка.

После заполнения и проверки каждого черновика человеком установите
`"annotation_status": "reviewed"`, затем выполните:

```powershell
.\.venv\Scripts\python.exe -m ai.labels build
```

Скрипт проверит формат, значения и точные цитаты. Только при полной валидности он создаст `data/labels/sft/train.jsonl` и `validation.jsonl` в формате conversational prompt/completion для [TRL SFTTrainer](https://huggingface.co/docs/trl/sft_trainer). Эти файлы тоже содержат тексты диалогов и не должны попадать в Git или публичный Hugging Face Hub.

В этой рабочей копии есть отдельные 15 предварительно размеченных чатов в
`data/labels/seed-drafts/`. Они имеют `annotation_status: "provisional"` и не являются
экспертным эталоном. Для пробного локального обучения их можно собрать явно:

```powershell
.\.venv\Scripts\python.exe -m ai.labels build --drafts data/labels/seed-drafts --out data/labels/seed-sft --allow-provisional
```

Получится 12 примеров для обучения и 3 для проверки. Для оценки качества
потребуется независимая экспертная проверка меток и более широкий набор.
Для просмотра этих предварительных оценок есть локальная таблица
`data/labels/seed-summary.csv`: ID, язык, все восемь ответов, итог и критерии с
`needs_review`. Ещё один предварительно размеченный звонок лежит отдельно в
`data/labels/voice-draft/`; он не входил в первый пробный запуск обучения.
При проверке звонка учитывайте возможные ошибки транскрипции, а не приписывайте
их оператору. После ручного просмотра исправьте спорные ответы и только тогда
поменяйте `annotation_status` на `reviewed` для проверенных файлов.

Текущий быстрый замер Gemini на трёх отложенных RU/KZ/EN чатах:

```powershell
.\.venv-dev\Scripts\python.exe -m ai.benchmark_gemini --allow-provisional
```

Локальный отчёт — `data/labels/gemini-benchmark.json`, он не публикуется. В последнем запуске все 3 ответа прошли проверку формата и цитат; медианное время 22.62 секунды, средняя абсолютная ошибка итогового балла против **предварительных** меток 12.28 пункта. По empathy совпали 2 из 3 ответов, по management — 1 из 3. Это указывает на необходимость экспертной разметки; три чата и предварительные метки не дают достоверную оценку точности.

## 3. Экспериментальное локальное обучение LoRA

Gemini доступен через API и не является базовой моделью для этого скрипта. Для LoRA используется открытая `Qwen/Qwen3-0.6B` по умолчанию; можно указать другую совместимую Qwen3 модель. Скрипт повторяет порядок из [PEFT Quicktour](https://huggingface.co/docs/peft/quicktour): загрузить базовую модель, задать `LoraConfig`, обернуть через `get_peft_model`, обучить и сохранить только адаптер. Данные не загружаются на Hub. Это отдельный опытный путь; обученный адаптер пока не подключён к backend.

Создайте **отдельное** окружение для обучения: новые библиотеки ML не должны менять
зависимости рабочего backend. Например, с `uv`:

```powershell
uv venv --python 3.12 .venv-train
uv pip install --python .venv-train\Scripts\python.exe -e .
uv pip install --python .venv-train\Scripts\python.exe torch==2.7.1 transformers==5.22.2 datasets==5.1.0 peft==0.21.2 trl==1.17.1 accelerate==1.15.0
```

Для CUDA-обучения замените обычную сборку `torch` на вариант по
[инструкции PyTorch](https://pytorch.org/get-started/locally/). После разметки и `build`:

```powershell
.\.venv-train\Scripts\python.exe -m ai.train_lora
```

Выход: `data/lora/qwen3-cqa/adapter/`. Скрипт использует CUDA, если она доступна;
`--device cpu` позволяет технически проверить обучение без неё, но работает медленнее.
Скрипт останавливается,
если пример будет обрезан длиной `--max-length`. Для пробного набора укажите
`--train data/labels/seed-sft/train.jsonl --validation data/labels/seed-sft/validation.jsonl`.
Адаптер и манифест обучения сохраняются локально в выбранном `--output`.
В этой рабочей копии веса `Qwen/Qwen3-0.6B` уже скачаны в локальную папку
`data/models/qwen3-0.6b/` и сверены по SHA-256. Один пробный шаг на CPU можно
запустить так:

```powershell
.\.venv-train\Scripts\python.exe -m ai.train_lora --train data/labels/seed-sft/train.jsonl --validation data/labels/seed-sft/validation.jsonl --model data/models/qwen3-0.6b --output data/lora/seed-qwen3 --device cpu --epochs 0.1 --max-length 4096
```

Проверка пайплайна на маленькой случайно инициализированной Qwen3-архитектуре прошла. Попытка одного шага с настоящими весами `Qwen3-0.6B` на CPU не закончилась за примерно 50 минут и была остановлена без сохранённого адаптера. Для практического обучения нужна CUDA-машина и проверенная человеком разметка; рабочий backend сейчас использует Gemini API, а не LoRA.
Проверка трёх отложенных чатов:

```powershell
.\.venv-train\Scripts\python.exe -m ai.evaluate_lora --adapter data/lora/seed-qwen3/adapter --validation data/labels/seed-sft/validation.jsonl --drafts data/labels/seed-drafts --output data/lora/seed-evaluation.json
```

Отчёт показывает, сколько ответов прошло проверку формата и цитат, совпадения по
критериям и ошибку итогового балла. Поскольку метки предварительные и выборка мала,
это техническая проверка обучения, а не доказательство качества для хакатона.
Сравните LoRA с Gemini на отложенных RU/KZ/EN примерах по каждому критерию,
N/A, флагу грубых ошибок и точности цитат, прежде чем менять рабочий evaluator.
