# Подключение фронтенда

Backend API уже работает. Для начала фронтендеру достаточно этой инструкции, [контракта](api-contract.md) и [Postman-коллекции](../examples/frontend/cqa.postman_collection.json). Реальная модель для первых экранов не нужна: демонстрационный сценарий использует ручные оценки с `origin: "manual"`.

Дополнение для новых функций: [пакетная обработка, Idempotency-Key, request ID и
отчёты](backend-operations.md). Текущие запросы frontend остаются совместимыми.
Для защиты от сетевых повторов сохраняйте один ключ на попытку пользователя;
для намеренной новой оценки создавайте новый. UI прогресса пакета и отчётов
пока не реализован: backend предоставляет маршруты и примеры для участника frontend.

Пакеты теперь можно восстанавливать через GET `/api/v1/evaluation-batches?limit=20&offset=0`:
ответ содержит краткие сведения и счётчики статусов. Подробности — прежний GET по ID.
POST создания пакета поддерживает Idempotency-Key: сохраняйте ключ до отправки,
при сетевом повторе передавайте прежние данные и ключ. Повтор возвращает исходный
снимок принятого пакета; актуальный прогресс перечитывайте GET-запросом.

## Быстрый старт без сервера и AI

После установки backend по [README](../README.md) выполните из корня репозитория:

```powershell
.\.venv\Scripts\python.exe scripts/frontend_kit.py
```

Скрипт запускает настоящий backend внутри процесса с отдельной временной SQLite, выполняет 16 HTTP-запросов и удаляет временную базу. Рабочая БД не используется. В `data/frontend-kit/` появятся:

| Файл | Назначение |
| --- | --- |
| `openapi.json` | Схемы запросов и ответов для импорта в инструменты или генерации типов выбранного фронтенд-стека |
| `responses.json` | Реальные ответы каждого шага: `responses[имя_шага].body`, HTTP-статус отдельно |
| `cqa.postman_collection.json` | Последовательный сценарий с автоматической передачей ID и проверками ответов |

Это искусственные примеры для UI, а не Ground Truth и не ответы AI. ID из временной базы пригодны только для просмотра JSON. Для настоящих запросов получите новые ID через импорт или запустите сценарий на работающем сервере. Повторный экспорт обновляет эти три файла; каталог `data/` исключён из Git.

## С работающим сервером

Первый терминал:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --env-file .env --host 127.0.0.1 --port 8000
```

Второй терминал:

```powershell
.\.venv\Scripts\python.exe scripts/frontend_kit.py --api http://127.0.0.1:8000
```

Теперь демо-набор, чек-лист, ручная оценка и её апелляция сохранены в рабочей БД. Их ID лежат в `responses.json` → `variables`. Каждый запуск создаёт новый набор и чек-лист; существующие данные не перезаписывает. Скрипт прекращает выполнение при несовпадении статуса/проверяемых полей и возвращает ненулевой код выхода. Это последовательность отдельных API-операций, поэтому уже созданные демо-записи остаются после ошибки. Автоматических повторов запросов нет.

В Postman импортируйте готовую коллекцию из `examples/frontend/`. Установите **collection variable** `base_url` в адрес backend без завершающего `/`. Запустите все запросы по порядку от `01-health` до `16-not-found`; `409`, `422` и `404` в последних шагах предусмотрены сценарием. ID и `revision` сохраняются автоматически. Не переопределяйте эти переменные в Environment: более узкая область переменных имеет приоритет. Повторный прогон начинайте с шага 01.

Механизм переменных и проверок: [переменные Postman](https://learning.postman.com/docs/use/send-requests/variables/variables/), [Sandbox API](https://learning.postman.com/docs/tests-and-scripts/write-scripts/postman-sandbox-reference/overview/).

## Что подключать на экранах

| Экран / действие | API | Что учитывать |
| --- | --- | --- |
| Готовность сервиса | `GET /health` | `ai_configured: false` — автопроверка недоступна, остальные функции работают |
| Импорт JSON | `POST /api/v1/datasets` | Отправлять `{name, group_id, records}`; ответ содержит ID набора |
| Список наборов | `GET /api/v1/datasets` | Список в `items`, не голый массив |
| Список диалогов | `GET /api/v1/datasets/{id}/conversations` | Фильтры `language`, `channel`; `total`, `limit`, `offset` для страниц |
| Диалог | `GET /api/v1/conversations/{id}` | Для запросов нужен внутренний `id`; исходный `conversation_id` предназначен для отображения |
| Выбор и редактор чек-листа | `GET/POST /api/v1/checklists`, `POST /api/v1/checklists/{id}/versions` | Поля формы строятся из критериев; сохранить выбранный ID и версию |
| Автооценка после подключения модели | `POST /api/v1/evaluations` | Явно передавать выбранную версию. Это синхронный запрос, а не фоновое задание |
| Просмотр оценки | `GET /api/v1/evaluations/{id}` | Показывать актуальные `final` и `score`, исходные `original` доступны отдельно |
| Апелляция и решение | `POST /api/v1/evaluations/{id}/appeals`, `POST /api/v1/appeals/{id}/decision` | Решение отправляет текущую `revision` как `expected_revision` |
| История | `GET /api/v1/conversations/{id}/evaluations` | Пагинация; пустой список — нормальное состояние |
| Экспорт | `GET /api/v1/datasets/{id}/export` | Сохранить JSON пользователю |

На каждом запросе показывать загрузку, успех или ошибку. При записи блокировать повторный клик, но не считать это серверной дедупликацией. После обрыва связи сначала перечитать историю. Для AI настроить клиентский тайм-аут больше `CQA_EVALUATION_TIMEOUT` (по умолчанию 180 секунд), иначе результат может сохраниться уже после отключения клиента.

Ошибка имеет форму `{"error":{"code":"...","message":"..."}}`; у `VALIDATION_ERROR` также есть `details`. В fetch проверяйте `response.ok`: ответ с HTTP 4xx/5xx нужно обработать явно. `409` требует перечитать объект; `503 AI_NOT_CONFIGURED` показывает недоступную модель. Не заменяйте ошибку демо-результатом. Полная таблица — в [контракте API](api-contract.md#ошибки).

Цитата ссылается на `message_id` сохранённого транскрипта. Балл берётся из backend: `0`, `null` и значение ответа `"na"` — разные состояния. Нарушения отображаются из `score.flags` отдельно. В демо есть binary/scale/flag, N/A и `needs_review`; исходный балл 75, после ручного пересмотра 100, исходная оценка сохраняется.

## Адрес сервера и CORS

В конфигурации фронта задайте базовый адрес `http://127.0.0.1:8000`; путь `/api/v1` уже входит в маршруты. Имя переменной зависит от выбранного frontend-стека. Секретная ссылка организаторов остаётся в серверном `.env`.

В `.env` backend укажите точный origin фронтенда, например:

```dotenv
CQA_CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173,http://localhost:3000
```

После изменения перезапустите backend. `localhost` и `127.0.0.1`, а также разные порты — разные origins. При разработке на двух компьютерах адрес API должен указывать на компьютер backend; сервер запускается с `--host 0.0.0.0`, а в CORS добавляется фактический origin фронта. В текущем backend нет авторизации: такой режим предназначен для доверенной сети команды.

## Поддержка набора

Источник последовательности — `examples/frontend/scenario.json`. Из него строятся Postman-запросы и Python-прогон, чтобы тела запросов не расходились. После изменения сценария выполните:

```powershell
.\.venv\Scripts\python.exe scripts/frontend_kit.py
Copy-Item data/frontend-kit/cqa.postman_collection.json examples/frontend/cqa.postman_collection.json
.\.venv\Scripts\python.exe -m pytest tests/integration/test_frontend_kit.py -q
```

Тест проверяет исполнение сценария настоящим backend и актуальность коллекции. Код frontend и реализация AI в этот набор не входят.

## Новые операции: отмена и качество

Готовые запросы: [backend-operations.http](../examples/frontend/backend-operations.http).
Это примеры контракта, реализация UI остаётся у frontend-участника.

- Кнопка «Отменить ожидающие» отправляет POST `/api/v1/evaluation-batches/{id}/cancel`
  без тела. Ответ — текущий BatchRecord. Не обещать остановить running: продолжать
  опрашивать GET, пока completed=false. Повтор отмены безопасен.
- `interrupted` + `BATCH_CANCELLED_BEFORE_START` отображать как «Отменено до запуска».
  `interrupted` + `RESTORE_REQUIRES_REVIEW` — «Требует проверки после восстановления».
  Другие interrupted могут означать оборванный вызов с неизвестным расходом.
- В расходе provider_not_called=true подтверждает нулевые вызовы и стоимость.
  Отсутствующее поле трактовать как false; known_calls=0 без calls_complete=true
  само по себе не доказывает бесплатность. Для нулевой стоимости без тарифа не
  добавлять произвольную валюту.
- Для quality пользователь явно выбирает manual ID, revision и AI ID. Отправить
  POST `/api/v1/reports/quality` с pairs как в examples/benchmark-manifest.json.
  Показывать покрытие, MAE и score_compared вместе; null означает отсутствие
  вычислимой метрики. Пары с issue показывать отдельно с причиной.
- REFERENCE_REVISION_CHANGED — обновить эталон и предложить явный выбор ревизии,
  не повторять автоматически с новым номером. При INPUT_MISMATCH показать, что
  сравнивать разные диалоги/версии/снимки входа нельзя. При отсутствии AI выбрать
  ai_id=null: это пропуск, а не нулевая ошибка и не успешная оценка.
- Подписать отчёт «Внутренние метрики команды». Он не измеряет официальное место
  в рейтинге; тестовые данные не подтверждают точность Gemini.

Пределы: 1000 пар, 8 MiB; 422 — ошибки выбора, 413 — размер. Отчёт доступен без
подключённой модели и не передаёт ей эталоны. Подробности и поля —
[backend-operations.md](backend-operations.md#8-отчёт-качества-по-http) и OpenAPI.
