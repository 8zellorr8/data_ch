# Локальный AI для backend

Модель — **Qwen3-1.7B + QLoRA NF4**, обучение и генерация выполняются на NVIDIA CUDA. API aijuju для этого не нужен. Сохранён контракт `Evaluator`; модель возвращает ответы и обоснования, итоговые баллы рассчитывает backend.

**Обнаруженное ограничение 1.7B:** дополнительная проверка показала одинаковый набор значений на всех 12 отложенных текстовых чатах. Эти значения совпадают с наиболее частыми метками обучающей выборки. Адаптер технически работает, но его нельзя считать проверенным самостоятельным оценщиком качества. Понижение loss и MAE относительно необученной базы не доказывает, что он учитывает содержание чата. До исправления требуется экспертная проверка оценок.

## Что передать

Код находится в ветке `codex/ai-gemini`. Помимо кода нужны:

- `data/models/qwen3-1.7b/` — официальные базовые веса и tokenizer [Qwen](https://huggingface.co/Qwen/Qwen3-1.7B), около 4,1 ГБ;
- `data/lora/qwen3-1.7b-compact/adapter/` и соседний `training-manifest.json` — обученный адаптер с tokenizer;
- CUDA-окружение по [ai-lora.md](ai-lora.md).

Диалоги DEV, API-ключи и базовые веса в Git не входят. На другой машине каталог базы разрешается относительно корня проекта; при необходимости задайте свой путь в поле `model` манифеста и `base_model_name_or_path` файла `adapter/adapter_config.json`.

Готовый адаптер: [закрытый GitHub Release](https://github.com/8zellorr8/data_ch/releases/tag/cqa-local-qwen3-1.7b-20261108). Распакуйте `cqa-qwen3-1.7b-qlora.zip` в корень проекта. Внутри есть переносимый манифест, tokenizer, лицензия базы и `local-ai.env` без ключей. Базовые веса скачиваются отдельно. Сохраните настройки существующего `.env`, перенеся в него параметры локального режима.

## Запуск

Из корня проекта в PowerShell, после установки ML-окружения:

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
.\.venv-train\Scripts\python.exe -m uvicorn ai.app:app --env-file .env --host 127.0.0.1 --port 8001 --workers 1
```

Обязательные настройки `.env`:

```dotenv
CQA_AI_PROVIDER=local-lora
CQA_LORA_ADAPTER=data/lora/qwen3-1.7b-compact/adapter
CQA_LORA_DEVICE=cuda
CQA_LORA_MAX_NEW_TOKENS=2048
CQA_LORA_TIMEOUT_SECONDS=150
CQA_EVALUATION_TIMEOUT=180
CQA_AI_CONCURRENCY=1
CQA_LLM_API_ENABLED=0
```

Модель загружается до запуска обработчика очереди. Одна GPU обслуживает оценки последовательно; используйте один процесс Uvicorn. Swagger находится на `http://127.0.0.1:8001/docs`, автоматическая оценка — `POST /api/v1/evaluations`. Остальные маршруты, сохранение, экспорт и очередь не меняются. Hosted entrypoint `ai.app:create_hosted_app --factory` использует тот же выбор модели.

Для внедрения в собственную фабрику:

```python
from ai.config import build_evaluator
from backend.main import create_app

app = create_app(evaluator=build_evaluator())
```

Этот вариант сам по себе не прогревает модель; вызовите `evaluator.warmup()` до запуска очереди либо используйте готовый `ai.app:app`. GPU должна находиться на машине backend. На хостинге без CUDA этот NF4-адаптер не запустится; существующий сайт автоматически не переключается на локальный компьютер.

## Формат и ограничения

Один диалог даёт один JSON со всеми критериями. Ограничение генерации задаёт допустимые значения, известные ID реплик и обязательные поля. Адаптер достаёт цитаты дословно из сообщений и строит обычный `EvaluationResult`. Это обеспечивает совпадение текста цитаты, но её смысловую уместность и правильность ответа нужно проверять отдельно.

Чаты RU/KZ/EN и пять транскриптов звонков входят в подготовленные данные. Аудио модель не слушает. Консультация требует проверки без продуктового FAQ, ведение звонка — без аудио. Длина входа ограничена манифестом; превышение возвращает явную ошибку, текст не обрезается.

Метки предварительные, экспертного эталона нет. Разделение — 52 обучающих и 13 отложенных диалогов; совпадающие числовые номера сценариев разных языков/каналов попадают в один раздел. Отчёты сравнивают с черновиками и не подтверждают качество на новых данных.

## Расход токенов

Для текущего локального запуска **новых платных API-вызовов нет**. Установлен общий порог 2 000 000 и начальный расход 809 000 со слов владельца, номинальный остаток — 1 191 000. Фактическое списание aijuju пока не сверено с их биллингом, поэтому платный API остаётся выключенным.

SQLite ledger резервирует `usage`-токены перед попыткой и учитывает неопределённые запросы консервативно. Он не ограничивает запросы других процессов и не гарантирует соответствие внутренним единицам оплаты провайдера. Новый ключ не обнуляет расходы. Не включайте платный режим только ради проверки локального адаптера.

Проверить локальный ledger без API-запроса:

```powershell
.\.venv-dev\Scripts\python.exe -m ai.budget data/aijuju-capped-budget.sqlite3
```

## Проверка 8 ноября 2026

Обучение на RTX 3050 Laptop 6GB завершено: 156 шагов за 990,49 секунды. Обучаются 1 605 632 параметра LoRA. На 13 отложенных диалогах:

| Метрика против предварительной разметки | База без обучения | После QLoRA |
| --- | --- | --- |
| Допустимые полные оценки | 13/13 | 13/13 |
| Совпадения ответов критериев | 56/104 | 82/104 |
| MAE итогового балла | 24,62 | 11,79 |
| Ложные N/A | 18 | 6 |

Улучшение неодинаково по критериям: контакт снизился с 12/13 до 11/13 совпадений, эмпатия осталась 11/13, грубые нарушения — 12/13. Экспертная точность не измерена. Адаптер требует проверки перед окончательной сдачей результатов.

Последующая проверка против частотного прогноза выявила проблему: на 12 текстовых чатах адаптер и постоянный прогноз по меткам TRAIN дают одинаковые 76/96 совпадений и MAE 12,35. Отдельный голосовой пример в первоначальных 13 результатах этого ограничения не устраняет. Подробности находятся в `follow_up_majority_audit` отчёта.

Подробные агрегаты: [ai-local-validation.json](ai-local-validation.json). Полный замер генерации выполнен до сокращения алфавита JSON-парсера; все 65 обучающих/проверочных целевых ответов и 13 фактических генераций принимаются сокращённой грамматикой. Повторный API-замер одного отложенного RU-диалога находится в `api_smoke.heldout_api_benchmark` отчёта. Оценка скорости на всём наборе после этой оптимизации отдельно не проводилась.

API создал восемь ответов, сохранил оценку в SQLite, повторно прочитал её и экспортировал набор. Синтетический чат — 30,52 секунды; отложенный RU-диалог — 28,57 секунды вместо 71,17 до оптимизации, значения всех критериев совпали. Для десяти PROD-чатов на этой GPU разумно заложить 5–15 минут последовательной обработки плюс время проверки и отправки результатов; это оценка, замер всего PROD ещё не проводился.
