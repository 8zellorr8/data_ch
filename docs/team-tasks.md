# Три человека, 22 часа

Главный приоритет — близость оценок к Ground Truth на новых диалогах.
Распределение ниже — исходный план команды на 22 часа. Сейчас backend и frontend
реализованы, демо развёрнуто; AI ещё не подключён. Актуальная приёмка без модели:
[backend-readiness.md](backend-readiness.md).

## 1. Ты — backend и интеграция

Владение: `backend/`, `tests/`, `scripts/`, зависимости и API-документация.

Уже сделано: импорт, SQLite, исходные 8 критериев, произвольные чек-листы, версии, сохранение оценок, проверка цитат и N/A, расчёт итогов, апелляции, JSON-экспорт. Модель подключается отдельным адаптером.

Следующая работа: подключить готовый адаптер участника 3 через hosted-фабрику,
проверить свежий набор, подготовить настоящие результаты и выполнить push.
Контракты уже доступны товарищам; изменения схем согласовывать между компонентами.
Не переносить вычисление итогового балла в UI или промпт.

Готовность: новый JSON импортируется, оценка реальной моделью сохраняется, версия правил зафиксирована, апелляция пересчитывает итог и сохраняет оригинал, экспорт открывается после перезапуска.

## 2. Участник 2 — frontend и демо

Владение: существующая папка `frontend/`. Стек: HTML/CSS/JavaScript без сборки.
Подключать экраны к существующему backend.

Порядок экранов:

1. Импорт JSON / импорт от организаторов, список наборов и фильтр RU/KZ/EN, чат/звонок.
2. Список диалогов → исходный транскрипт с ролями, временем и ID сообщений.
3. Выбор версии чек-листа и кнопка оценки; прогресс и понятная ошибка, если модель не подключена.
4. Таблица критериев: значение, пояснение, цитата со ссылкой на сообщение, N/A, флаг нарушения и отметка ручной проверки. Итог брать из `score.total`.
5. Редактор чек-листа с созданием новой версии. Произвольный новый критерий должен работать через те же компоненты.
6. Апелляция и решение с цитатой; исходная и итоговая оценки рядом; кнопка JSON-экспорта.

До готовности модели использовать явно подписанную **ручную оценку** `/evaluations/manual`; не показывать её как AI. Не вставлять ключи и подписанную ссылку организаторов в браузерный код.

Готовность: полный путь от загрузки до экспорта без Swagger, понятные состояния загрузки/ошибок и отсутствие захардкоженных восьми строк в UI.

## 3. Участник 3 — AI и точность

Владение: будущая папка `ai/`, промпты, локальные файлы разметки и скрипт сравнения. Контракт — `docs/ai-integration.md`.

1. Проверить доступный API или оборудование для локальной модели. Начать с одного работающего провайдера; локальную модель подключить следующим этапом, если подходит по скорости и качеству.
2. Реализовать `Evaluator`, который получает **новый полный диалог и выбранную версию правил**, возвращает структурированные ответы с точными цитатами.
3. Сделать небольшой вручную размеченный набор RU/KZ/EN и звонков. Разделить примеры для настройки и проверки. Ручные оценки команды не называть официальным Ground Truth.
4. Проверять N/A, идентификацию, полноту консультации, эмпатию, завершение и отдельный флаг нарушений. Не штрафовать за непроверяемые продуктовые факты или свойства голоса; использовать `needs_review` и `limitation`.
5. Сравнивать по критериям и по итоговому баллу: доля точных совпадений, MAE, ошибки N/A, время. Официальная формула сравнения с Ground Truth пока неизвестна, это внутренние метрики.
6. При необходимости добавить повторную проверку спорных ответов. Записывать модель, версию промпта, число вызовов и доступную статистику токенов.

Готовность: минимум один реальный вызов, корректная схема и цитаты, работа на незнакомом диалоге и новом чек-листе, отчёт об ошибках на отложенных примерах.

| Часы | Backend | Frontend | AI |
| --- | --- | --- | --- |
| 0–2 | Запуск, импорт, фиксация контрактов | Каркас экранов, список и транскрипт | Провайдер, контракт, первый реальный ответ |
| 2–7 | Помощь с интеграцией, ошибки API | Оценка с цитатами, редактор правил | Промпт и ручная разметка части DEV |
| 7–12 | Подключение адаптера, сквозной сценарий | Апелляции, экспорт, пакетный прогресс | Сравнение, разбор расхождений, RU/KZ/EN |
| 12–17 | Тест нового набора, перезапуск и сохранность | Исправления UX, тест нового критерия | Проверка на отложенных примерах, стабильность |
| 17–20 | Заморозить API, README запуска | Демо и скриншоты | Зафиксировать модель/промпт/результаты |
| 20–22 | Чистый запуск из клона, резерв времени | Репетиция 5 минут | Проверка незнакомого транскрипта |

Если время уже потрачено, сначала обеспечить сквозной путь «новый диалог → реальная AI-оценка → цитаты → экспорт», затем расширять.

## Работа в Git

Рабочая backend-ветка: `codex/backend-core`; frontend уже находится в этой ветке.
AI-участник интегрирует свой адаптер отдельным коммитом, ориентируясь на
[контракт](ai-integration.md). Каждый работает преимущественно в своей области.
Изменения `backend/models.py` согласовываются между компонентами. Репозиторий
8zellorr8/data_ch сейчас публичный; секреты, исходные DEV-диалоги и записи звонков
не коммитить. Предусмотренные организаторами результаты JSON публикуются отдельно
по [инструкции сдачи](submission.md). Демо на alwaysdata работает без AI;
новую серверную фабрику нужно развёртывать при подключении готового адаптера.
