# Работа команды перед сдачей

Обновлено 8 ноября 2026 года. Общая версия — `main`; frontend, backend и AI
объединены коммитом `652618e`. Исходный план на 22 часа больше не отражает
готовность проекта. Требования и сценарии: [acceptance.md](acceptance.md).
Порядок работы с ветками: [team-workflow.md](team-workflow.md).

## Backend и интеграция

Владение: `backend/`, backend-тесты, `scripts/`, зависимости и API-документация.

Реализованы импорт, версии чек-листов, формула, проверка цитат, исходные оценки,
апелляции, пакеты/отмена/возобновление после 429, отчёты, backup/restore и экспорт
JSON 1.0. CLI `submission_check` проверяет готовность экспорта и существующий
файл без вызова модели; команды и коды выхода — в [submission.md](submission.md).

Оставшиеся действия:

1. Получить от AI-участника реальные результаты и метаданные. Его локальные
   файлы автопроверки не являются автоматически записями общей БД или сдаваемым
   JSON. Согласовать проверяемый перенос либо итоговый прогон через общий backend.
2. С выбранным провайдером пройти путь «новый диалог → реальная оценка → хранение
   → чтение → экспорт», измерить число обращений и расход с учётом повторов.
3. Проверить готовность, скачать и сверить DEV-файл; при получении контрольного
   набора повторить для PROD. Сделать commit и push до стоп-кода.
4. Отдельно обновить alwaysdata и проверить сохранность базы. Push в main сервер
   не переключает; последняя подтверждённая серверная версия — `d88ba31`.

Формула и API остаются в backend. Изменения контрактов согласуются с двумя участниками.

## Frontend и демонстрация

Владение: `frontend/`. Интерфейс уже включает импорт, диалоги, редактор чек-листов,
оценки/цитаты, апелляции, пакеты, отчёты и сдачу. Новые экраны с нуля не нужны.

1. Пройти M02–M10 из плана приёмки: ссылки на цитаты, N/A, исходный/финальный
   результат, апелляции и конфликт двух вкладок. Проверить звонок и ссылку на запись.
2. Через UI заменить критерий, сохранить новую версию и применить её к новому
   диалогу с реальной моделью. Это отдельная проверка организаторов.
3. Проверить ошибки провайдера и пакетный прогресс. Ручное resume после исчерпания
   автоматических 429-повторов пока доступно через API; отдельной кнопки нет.
4. Провести демонстрацию за пять минут и проверить мобильный браузер.

Локальная работа с локальным backend:
`python frontend/serve.py --api http://127.0.0.1:8000`.
Запуск без `--api` работает с общим сервером команды и меняет его данные.

## AI и проверка точности

Владение: `ai/`, промпты, адаптеры и приватные файлы разметки.
Контракт: [ai-integration.md](ai-integration.md).

1. Зафиксировать провайдера, точную модель, настройки и доступную квоту. При смене
   провайдера передать backend документацию: endpoint, формат авторизации и пример
   запроса без ключа. Наличие Gemini-адаптера не доказывает совместимость AI juju.
2. Передать сохранённые 65 DEV-оценок и метаданные, описанные в
   [отчёте AI-участника](ai-provider-check.md). Не публиковать исходные транскрипты.
3. Проверить новые диалоги, RU/KZ/EN, звонки и произвольный изменённый критерий.
   Сохранять дословные цитаты, версию промпта, фактическую модель и все обращения.
4. Согласовать человеческие оценки на небольшой выборке. Предварительная разметка
   ассистента и DEV, использованный для настройки, не являются независимым
   Ground Truth. В первую очередь разобрать ведение диалога и консультацию.
5. Сохранить ограничение каждого обращения и безопасную обработку квот.
   Число оценок не равно числу API-вызовов. Для платного API указать примерную
   стоимость оценки со всеми повторами; burn-единицы не выдавать за обычные токены.

## Общая готовность

- Один сквозной сценарий на общей версии с реальной моделью выполнен через UI.
- Замена критерия без правки кода и апелляция продемонстрированы.
- Файлы DEV/PROD проверены и доступны в удалённом Git до стоп-кода.
- Зафиксированы финальный SHA, модель/промпт, время контроля и порядок получения PROD.
- README и пятиминутная демонстрация соответствуют сдаваемой версии.

Автоматические тесты используют синтетические ответы. `submission_check` проверяет
пригодность выгрузки, но не точность модели, оплату/квоту, дедлайн или наличие push.
Регистрация, локальная модель и обучение собственной модели по гайду не обязательны.
