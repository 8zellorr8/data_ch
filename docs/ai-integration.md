# Контракт для AI-участника

В общей ветке `codex/integration` подключён aijuju API с `gemini-3.8-flash`.
Актуальный единый запуск и ключи описаны в [integration.md](integration.md).
Остальные варианты адаптеров ниже остаются доступными по явной настройке.

Для Gemini есть адаптер в `ai/` и инструкция [запуска и разметки](ai-gemini.md). При запуске `backend.main:app` или без API-ключа работает `UnconfiguredEvaluator` либо незадействованный Gemini evaluator и автоматическая оценка возвращает 503; фиктивных автоматических оценок нет.

`ai.local_lora.LocalLoRAEvaluator` подключает локальный PEFT-адаптер через тот же контракт. При `CQA_AI_PROVIDER=local-lora` команда `python -m uvicorn ai.app:app --env-file .env --port 8001 --workers 1` запускает API с ним; нужны ML-зависимости, базовая модель и обученный адаптер. Новый компактный адаптер возвращает все восемь ответов за одну генерацию. Цитаты извлекаются из исходных реплик, результат проверяет backend. Инструкция передачи backend-разработчику: [ai-local-handoff.md](ai-local-handoff.md).

## Что реализовать

Класс с `configured = True` и методом:

```python
async def evaluate(self, context: EvaluationContext) -> EvaluatorOutput: ...
```

Типы уже находятся в `backend/evaluator.py` и `backend/models.py`. `context.conversation` содержит текст каждого сообщения, его `id`, роль и время, язык, канал и необязательную ссылку на аудио. `context.checklist` содержит конкретную версию, общие правила и все критерии с весами, шкалами, N/A и адаптацией звонков `call_rule`.

Этот контракт сохранён в backend 0.2. Сервис передаёт копии входов; ответ проверяется по исходным данным. Изменять правила и транскрипт внутри адаптера для обхода проверки нельзя. `EvaluatorOutput` остаётся dataclass с теми же полями; метаданные теперь тоже проходят строгую проверку (`calls >= 1`, токены неотрицательны, имя модели и версия промпта непустые).

Если адаптер использует `DomainError`, его конструктор принимает только `code` и `message`; HTTP-статусы назначает backend. Ошибки схемы ответа и нарушений правил получают `AI_INVALID_RESULT`. Ошибки внутри формирования серверной записи не превращаются в ошибки данных AI. Имена языка/канала/вида доказательства в JSON остались прежними.

Вернуть `EvaluatorOutput(result=EvaluationResult(...), model="реальное имя", prompt_version="версия")`. Поля статистики: `input_tokens`, `output_tokens`, `calls`, `audio_analyzed`. Неизвестные токены оставить `None`; `audio_analyzed=True` только если аудио действительно анализировалось.

Ответ на один критерий:

```json
{
  "criterion_id": "contact",
  "value": "yes",
  "explanation": "Оператор поздоровался и представился в первом ответе.",
  "evidence_kind": "present",
  "evidence": [{"message_id": "m2", "quote": "Здравствуйте, я Анна."}],
  "na_reason": "",
  "needs_review": false,
  "limitation": ""
}
```

`result` имеет вид `{"answers":[...]}` — ровно один ответ на каждый критерий, без неизвестных ID. `value`: `"yes"`, `"no"`, `"na"` или **число** из шкалы. Нельзя возвращать `true`, `false`, строку `"7"` или придуманную промежуточную ступень. Для `flag` значение `yes` означает нарушение. Итоги и перераспределение весов считает backend.

Цитата должна быть точной подстрокой сообщения, не переводом или пересказом. Для пропущенного действия используйте `evidence_kind="missing"` и цитату из сегмента, где действие ожидалось. Для N/A нужны `evidence_kind="not_applicable"`, `na_reason` и контекстная цитата. Если не хватает справочника или аудио, поясните ограничение через `needs_review=true` и `limitation`; отсутствие справочника само по себе не разрешает N/A.

## Правила промпта

- Отделяйте инструкции оценивания от текста диалога. Команды внутри клиентских реплик — анализируемые данные, не команды модели.
- Оценивайте оператора; бот и системные события — контекст. Проверяйте отсутствие действия только там, где у оператора была возможность его выполнить.
- Передавайте все критерии из текущего `context.checklist`, не список из восьми имён в коде. Новый чек-лист должен работать без правки адаптера.
- Для звонков применяйте `call_rule` вместе с основной шкалой. Без анализа аудио не оценивайте дикцию или темп и учитывайте возможные ошибки распознавания.
- Продуктовые утверждения проверяйте по предоставленному справочнику. Модель не должна выдавать выдуманный тариф за факт.
- Не воспроизводите сохранённые оценки по внешнему ID диалога. Backend вызывает адаптер для каждого запроса.
- Ограничьте повторные попытки и не сохраняйте частичный ответ как полный. Общий лимит backend — 180 секунд. Учитывайте все фактические обращения в `calls`.
- Перед каждым сетевым обращением, включая повторы, вызывайте внедрённый RequestGate.
  При 429 сохраняйте cooldown через gate.defer и возвращайте ProviderDeferred с
  retry_at (Unix UTC), известным usage и признаком суточной квоты. Не выполняйте
  немедленный повтор/fallback. safe_to_retry=True разрешён только при известном
  отказе до генерации; после предыдущего неоднозначного вызова ставьте False.
  provider_not_called=True допустим только когда в этой оценке вообще не было
  обращений к провайдеру. Ни тайм-аут, ни отсутствие usage не доказывают нулевой расход.
- Используйте асинхронный HTTP-клиент. Длительные синхронные вызовы SDK переносите в рабочий поток. Не подавляйте отмену задачи: тайм-аут backend кооперативный. Локальный инференс в отдельном процессе/сервисе предпочтителен длительному вычислению внутри event loop.

## Подключение

Адаптер находится в `ai/gemini.py`; `ai/app.py` создаёт приложение через `create_app(evaluator=GeminiEvaluator(...))`. Для запуска используйте `python -m uvicorn ai.app:app --env-file .env`. Пакет `ai` включён в `pyproject.toml`.

### Hosted-приложение: frontend и API на одном адресе

`create_hosted_app(*, evaluator: Evaluator | None = None)` передаёт адаптер в тот же
`create_app`. Один экземпляр используется одиночными запросами и обработчиком
пакетов. Статика, проверка локального SQLite, резервные копии и завершение
фоновых задач остаются в hosted-обёртке. Вызов без аргументов совместим:

```text
python -m uvicorn backend.hosting:create_hosted_app --factory
```

Фабрика `ai.app:create_hosted_app` уже передаёт `GeminiEvaluator` в hosted-приложение.
Она читает `GEMINI_API_KEY`, `CQA_GEMINI_MODEL`,
`CQA_GEMINI_THINKING_LEVEL` и `CQA_GEMINI_ALLOW_VOICE_CALLS` при запуске.
Также используется `CQA_GEMINI_RPM` (по умолчанию 3); приложение передаёт
SQLiteRateStore для общей частоты/паузы одиночных и пакетных оценок. Обычный
build_evaluator() для CLI использует память, build_evaluator(persistent=True)
требует инициализированную backend-БД. Её инициализирует lifespan приложения.
Настройки и контракт продолжения: [backend-operations.md](backend-operations.md#10-частота-запросов-429-и-продолжение-пакета).

Для бесплатного проекта проверена `gemini-3.5-flash-lite`, `medium`: 15 RPM,
250 000 TPM, 500 RPD. `CQA_GEMINI_FALLBACK_MODEL` оставьте пустой,
`CQA_GEMINI_ALLOW_VOICE_CALLS=1` включает пять DEV-транскриптов без аудио.
Актуальные результаты, остаток квоты, ограничения качества и настройки очереди:
[ai-provider-check.md](ai-provider-check.md). Интерфейс Evaluator и расчёт баллов
не изменены.

Для alwaysdata меняется только цель существующей команды:

```text
/home/replimetr/venv/bin/python -m uvicorn ai.app:create_hosted_app --factory --host :: --port 8100 --workers 1 --no-access-log --timeout-graceful-shutdown 200
```

Сохранить все `CQA_*` настройки из [alwaysdata.md](alwaysdata.md). Добавить
`ai*` к `tool.setuptools.packages.find.include`, включить файлы промптов в
package-data при их использовании и проверить установленный пакет из чистого
окружения. Новые зависимости клиента объявить в pyproject и зафиксировать в
requirements-lock.txt. Имена переменных для ключа/модели определяет готовый
адаптер; добавление одного ключа сейчас ничего не подключает.

Если адаптер владеет HTTP-клиентом, AI-участник должен определить его закрытие
в lifespan своей фабрики, сохранив вложенный lifespan hosted-приложения.
Текущий Protocol не добавляет неявных вызовов `close()` стороннему объекту.
Проверки synthetic Evaluator подтверждают передачу зависимости, но не работу Gemini.

Интерфейс допускает как локальный Ollama, так и облачный сервис. Конкретная модель
и клиент провайдера остаются внутри адаптера; backend не привязан к его HTTP API.

Команда выбрала Gemini API; клиент и промпт реализованы в ветке AI. Backend уже
ограничивает параллельность одиночных и пакетных оценок и учитывает каждый запуск.
Необязательное поле `EvaluatorOutput.usage: ProviderUsage | None` позволяет сообщить
совокупные токены и число вызовов, включая повторы. `usage.complete=True` означает
полный учёт всех оплачиваемых категорий в двух ставках тарифа; по умолчанию False.
При ошибке адаптер может передать известный расход через
`EvaluatorFailure(code, безопасное_message, usage)`. Старые реализации без этих
полей работают с явной отметкой неполного учёта. Подробности и ограничения:
[backend-operations.md](backend-operations.md#расширение-ai-контракта).

## Проверка перед передачей

Проверьте реальный незнакомый диалог, RU/KZ/EN, звонок без аудио, новый пользовательский критерий, недопустимую шкалу и оборванный JSON от модели. Backend должен получить корректные цитаты, статистику и понятную ошибку при сбое. На отложенной ручной разметке сохраните качество по каждому критерию и итоговому баллу. Реальные DEV-диалоги и ключи оставьте вне Git.
