# Репетиция backend и сдачи без AI

Из корня установленного проекта выполните одну команду:

```text
python -m scripts.rehearse_backend
```

На Windows без активации venv:

```powershell
.\.venv\Scripts\python.exe -m scripts.rehearse_backend
```

Нужны зависимости проекта и локальные TCP-сокеты. Docker, ключи, внешний сервер,
доступ к интернету и `.env` для репетиции не нужны. Установка зависимостей —
по [README](../README.md); сама команда ничего не устанавливает.

## Что проверяется

1. Создаётся отдельная временная SQLite и отдельный процесс настоящего Uvicorn
   на `127.0.0.1` со свободным портом. Запускается production backend.main с
   UnconfiguredEvaluator. Модель или тестовый Evaluator не подставляются.
2. Выполняются готовые 16 шагов из `scripts/frontend_kit.py`: импорт, чтение,
   пользовательский чек-лист, ручная оценка с цитатами и N/A, апелляция и экспорт.
   Исходный балл 75 сохранён; итог после пересмотра 100, ревизия 2.
3. Повтор решения получает APPEAL_CLOSED и не меняет сохранённую оценку.
   Создаётся версия чек-листа 2 с изменённым правилом и применяется к новой
   ручной оценке; предыдущая оценка сохраняет исходную версию.
4. Запрос автоматической оценки получает ожидаемый 503 AI_NOT_CONFIGURED.
   Проверяется, что успешная AI-оценка не появилась.
5. Импортируются отдельные синтетические наборы: DEV — 60 чатов/5 звонков,
   35 RU/15 KZ/15 EN; PROD — 10 чатов. Это искусственные примеры, не данные
   организаторов и не проверка качества обработки языков.
6. Для всех 65/10 диалогов явно задаются ошибки AI_NOT_CONFIGURED. Реальных
   попыток вызова модели нет. `submission_cli` и `submission_remote` запускаются
   отдельными процессами и должны вернуть одинаковые JSON 1.0. Проверяются все
   исходные ID, пустые criteria и score=null у ошибок.
7. `submission_check` локально и по HTTP должен вернуть
   export_ready_with_errors, код 1, ноль успешных оценок и все ошибочные ID.
   Отдельный повреждённый файл получает RESULTS_MISMATCH/код 2; старый
   submission_cli --check тоже должен его отвергнуть.
8. Ручная оценка того же PROD-диалога не принимается как AI-результат:
   HTTP и локальная проверка должны вернуть INVALID_SUBMISSION.
9. Первый процесс штатно останавливается; второй открывает ту же временную БД.
   Сравниваются все три набора, исходные/итоговые оценки, версии и история
   апелляций. Исключается только время формирования архива exported_at.

Формат model.name обязателен даже в файле с ошибками. Здесь используется явный
маркер `not-run-no-ai-rehearsal`; это не название реально вызванной модели.
Эти файлы нельзя публиковать вместо официальных DEV/PROD-результатов.

## Изоляция и завершение

- Рабочие `.env`, БД и файлы results/ не читаются и не изменяются. Файлы сценария
  берутся только из синтетических examples/. Дочерние процессы получают
  разрешённый минимум системных переменных и собственные CQA-настройки.
  Ключи, сторонние CQA-настройки, proxy, Basic Auth и Python hooks не наследуются.
- HTTP-клиенты используют trust_env=False, обращаются только к адресу собственного
  процесса и не следуют перенаправлениям. Мутации не повторяются; повторяются
  только чтения /health во время ожидания запуска.
- Порт привязывается в дочернем процессе и остаётся занятым им до остановки:
  нет промежутка между поиском свободного порта и его использованием.
- Временная папка должна находиться вне репозитория. Если системный TEMP/TMPDIR
  указывает внутрь проекта, команда отказывается создавать файлы.
- Остановка выполняется через собственный multiprocessing.Event. При зависании
  terminate/kill применяются только к объекту процесса, созданному этим запуском;
  принудительная остановка не считается успешной репетицией.
- Для CLI предусмотрено ожидание до 30 секунд. При тайм-ауте его дочерний процесс
  завершается, затем закрывается сервер. Временные файлы удаляются также при
  исключении или обрабатываемом Ctrl+C. Принудительное завершение самого
  родительского Python или отключение питания не даёт гарантии очистки.
- Скрипт не выполняет Git, не обращается к alwaysdata и не меняет API или схему БД.

## Результат команды

`PASS` отмечает пройденные этапы; последняя строка `OK` содержит длительность.
Код выхода всей репетиции 0 означает, что технический сценарий прошёл. Ожидаемые
ошибки вложенных команд (1 для неоценённых диалогов, 2 для неверного файла/ручной
подмены) проверяются явно. Любое неожиданное поведение даёт код 1 с причиной.

Технический успех не означает, что у команды есть AI-оценки для сдачи.
Репетиция **не проверяет** точность модели, доступность провайдера, реальную квоту,
стоимость и время обработки контрольного набора. Работа интерфейса в браузере
также проверяется отдельно.

## После подключения AI

Нужно отдельно пройти новый диалог → реальный вызов → цитаты → хранение →
официальный экспорт; проверить изменённый через UI критерий, RU/KZ/EN и звонок.
Затем сравнить результаты с человеческой разметкой, измерить время и расход,
выпустить настоящие results/dev/results.json и results/prod/results.json и
проверить push до стоп-кода. [Порядок сдачи](submission.md).
