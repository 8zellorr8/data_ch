## Подтверждено

- Реальный Gemini 3.6 Flash: синтетический RU-чат, 1 вызов, 8 ответов, корректные
  значения и точные цитаты. 1540 входных и 1019 выходных/мыслительных токенов
  по ответу провайдера. Итог 100 рассчитан backend; это результат конкретного
  синтетического примера, а не показатель точности модели.
- Интеграционные тесты используют настоящий адаптер и SQLite с подменённым HTTP
  провайдера: RU/KZ/EN, транскрипт звонка при явном включении, новый чек-лист,
  одиночная оценка, идемпотентный повтор, пакет и сохранность после перезапуска.
  Подменённые ответы не являются результатами Gemini.
- Docker включает `ai/` и запускает `ai.app:app`. Без ключа остаётся ручной режим.
- Ключ хранится в игнорируемой `.env`; в Git и Docker-образ он не включается.
- 300 тестов, Ruff, проверка форматирования (69 файлов), mypy (40 файлов) прошли
  локально. [CI коммита объединения](https://github.com/8zellorr8/data_ch/actions/runs/42394726697)
  прошёл на Python 3.11/3.12, включая Docker smoke. Локальный Docker daemon не был
  запущен; проверку контейнера выполнил CI.
- alwaysdata обновлён до `4ebace2`, ключ и Gemini 3.6 Flash настроены в окружении
  сайта. После перезапуска сохранились наборы, исходная ручная оценка 75, итог 100,
  ревизия 2 и решение апелляции. Служебные файлы не доступны по HTTP.
- Проверка настоящей модели через сайт вернула `502 AI_UNAVAILABLE` с сообщением
  `Gemini API returned HTTP 429`. Отдельный диагностический запрос подтвердил
  `RESOURCE_EXHAUSTED`, `GenerateRequestsPerDayPerProjectPerModel-FreeTier`, лимит
  20 и `retryDelay=53045s`. Это состояние проекта при проверке, не общий тариф Gemini.
  Успешная AI-оценка на сайте не создана; неудача не записана как успех.

## Исправлено при объединении

- Пакет AI отсутствовал в Dockerfile, разрешённых файлах контекста сборки и Docker smoke.
- При переключении модели токены разных моделей ошибочно суммировались под одним
  именем тарифа. Теперь такой расход явно неизвестен, число обращений сохранено.
- Добавлены проверки конечных положительных тайм-аутов и допустимого имени модели.
- Добавлена команда `python -m ai.check_connection --env-file .env --live`.
- Обновлены команды запуска, архитектура и инструкции для `main`.

## До сдачи ещё нужно

1. Независимая ручная разметка и quality report с конкретными ID AI/эталонов и ревизиями.
   Упомянутые AI-разработчиком три предварительных примера не доказывают точность.
2. Полный прогон DEV и проверенная выгрузка `results/dev/results.json`, затем PROD
   в отведённый организаторами час. В этом интеграционном прогоне DEV не отправлялся.
3. Для звонков явно настроить `CQA_GEMINI_ALLOW_VOICE_CALLS=1` после решения команды
   об отправке этих данных. Аудио не анализируется даже при включённой настройке.
4. Продуктовый справочник не подключён. Модель должна обозначать неопределённость,
   а не выдумывать факты о тарифах и услугах.
5. LoRA остаётся экспериментом: есть отдельная точка входа `ai.local_app:app`,
   но проверенное качество локальной модели не подтверждено, на хостинге она не запускается.
6. После восстановления квоты повторить один синтетический запрос через сайт,
   проверить его сохранение и идемпотентный повтор, затем планировать DEV/PROD.
   Нынешнего суточного лимита 20 недостаточно для полного DEV из 65 разговоров
   за сутки; повторы дополнительно расходуют доступные обращения.
   Настройки и код alwaysdata обновляются отдельно от Git push:
   [alwaysdata.md](alwaysdata.md).

API-форматы, расчёт, история исходных оценок и апелляций сохранены.
