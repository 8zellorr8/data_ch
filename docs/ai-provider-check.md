## Передача backend

Серверные настройки:

```dotenv
CQA_GEMINI_MODEL=gemini-3.5-flash-lite
CQA_GEMINI_FALLBACK_MODEL=
CQA_GEMINI_THINKING_LEVEL=medium
CQA_GEMINI_ALLOW_VOICE_CALLS=1
```

Существующий `GEMINI_API_KEY` берётся из секретного окружения сервера. Локальный `.env` уже обновлён; сервер Replimetr из этой рабочей копии не перенастраивался. На сервере нужны эти значения и перезапуск `ai.app:create_hosted_app`.

`Evaluator`, `EvaluatorOutput` и `{"answers":[...]}` сохранены. Модель возвращает ответы, причины и цитаты; балл, веса, N/A и итог считает backend. Сохраняются фактическая модель, версия промпта, токены и `calls`. Звонки оцениваются по тексту, `audio_analyzed=false`; дикция и интонация без аудио не оцениваются.

У Lite по умолчанию максимум две попытки по 40 с; отдельной резервной модели нет. Считайте квоту по **обращениям к провайдеру**, включая повторы. Для очереди, ограничивающей только оценки, консервативный старт — один работник и до пяти оценок в минуту: до десяти обращений при двух попытках на каждую. Общий ограничитель RPM/TPM и сохранение очереди остаются на стороне backend, как согласовано.

HTTP 503 и сетевые ошибки встречались в реальном прогоне. Повторно ставьте неуспешные элементы после паузы, сохраняя успешные; для PROD это часть рабочего сценария, даже при достаточной квоте. 429 проверяйте отдельно: исчерпанный RPD не устраняется короткой паузой или новым ключом.

Ориентир по фактическому DEV-прогону: **65 DEV — 15–20 минут, 10 PROD — примерно 3–5 минут**, плюс запас на сеть, 503, экспорт и push. Длительный сбой Google может увеличить это время. Перед PROD проверьте актуальную квоту в AI Studio. Один запуск 75 оценок при двух попытках на каждую требует до 150 обращений; повторная постановка ошибок в очередь расходует квоту дополнительно. Полная квота 500 RPD даёт запас, но отображаемый остаток после сегодняшних экспериментов — 238 с задержкой обновления.

## Воспроизводимый DEV-прогон

```powershell
.\.venv-dev\Scripts\python.exe -m ai.autolabel "C:\Users\erken\Downloads\Doomsday\invoke.json" --out data/labels/lite-final-medium --include-voice --balanced-order --min-interval 12
```

Скрипт атомарно сохраняет только проверенные результаты и при повторном запуске переиспользует их. Он отказывается смешивать разные диалоги, чек-листы, модели, версии промпта или thinking в одной папке. `--ids-file` выбирает JSON-массив ID, `--diagnostics-dir` явно включает локальное сохранение невалидных ответов для разбора; эти файлы содержат тексты и остаются вне Git. Это инструмент подготовки/проверки данных, он не заменяет серверную очередь.

## После объединения с backend

Этот отчёт описывает запуск AI-участника до объединения веток. В main сохранены
SQLite-очередь, отложенные повторы после 429 и общий серверный лимитер каждого
сетевого запроса: `CQA_GEMINI_RPM=3` по умолчанию. `ai.autolabel` также учитывает
эту настройку, но использует отдельный лимитер в памяти процесса.
`--min-interval` ограничивает старты оценок дополнительно, не заменяет RPM
для повторов. Поэтому указанные выше времена не являются обещанием времени
обработки на хостинге с настройками по умолчанию. Безопасное продолжение 429
описано в [backend-operations.md](backend-operations.md#10-частота-запросов-429-и-продолжение-пакета).
Сетевые ошибки с неизвестным исходом автоматически через resume не повторяются.
