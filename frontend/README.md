# Replimetr — frontend

HTML, CSS и JavaScript для Replimetr API 0.2.0. Контракт сверён с backend `695ab11` ветки `codex/backend-core`. Сборка и npm-зависимости не нужны. Название интерфейса остаётся Replimetr.

## Запуск с общим сервером команды

Из корня репозитория:

```powershell
python frontend/serve.py
```

Открыть **http://127.0.0.1:5173/?server=team**. Этот адрес выбирает общий сервер даже при сохранённой настройке старого локального backend. Из папки `frontend` можно выполнить `npm start` или `python serve.py`.

`serve.py` отдаёт интерфейс и передаёт только `/health` и `/api/v1/*` на `https://replimetr.alwaysdata.net`. Браузер обращается к одному origin; это решает запрет CORS размещённого API для localhost. Python использует стандартную библиотеку, слушает только 127.0.0.1, сохраняет Idempotency-Key и диагностические ID, не повторяет POST автоматически. Ключи модели и подписанная ссылка организаторов здесь не нужны.

Для другого локального backend:

```powershell
python frontend/serve.py --api http://127.0.0.1:8000
```

Нужна актуальная версия backend: старый архив не содержит пакеты и отчёты. Backend запускается отдельно по его README. Прямой адрес API также можно выбрать шестерёнкой; при прямом обращении backend должен разрешать origin фронтенда через CORS. На размещённом сайте UI по умолчанию использует свой origin. Не открывайте index.html двойным щелчком и не заменяйте `serve.py` обычным http.server при работе с общим API.

После обновления открытой страницы — **Ctrl+F5**. Завершить локальный сервер — Ctrl+C.

## Возможности

- Импорт JSON и серверный импорт по произвольному `group_id`; наборы, языки RU/KZ/EN, чаты и звонки, роли, временные отметки и аудиоссылка.
- Фильтры и сортировка всего набора до пагинации: без оценки, нужна проверка, подтверждённое нарушение, язык, канал, ID, балл. Выбор страницы или всех результатов.
- Динамические чек-листы и версии, шкалы, N/A, правила звонков. Из карточки можно сохранить новую версию и явно применить её к тому же диалогу.
- Одиночная AI-оценка и явно ручная оценка, все цитаты модели, переход к сообщению, needs_review/limitation, объяснения N/A и отсутствующего действия.
- Исходный и текущий результат, снимки правил, история, апелляции и защита expected_revision. HTTP409 не вызывает слепое повторное решение.
- Серверные пакеты 1–100 диалогов: закреплённая версия, прогресс, восстановление списка, результаты и ошибки. Опрос каждые 2,5 секунды прекращается при завершении/уходе. «Отменить ожидающие» отменяет только pending; running продолжает работу. Завершённый пакет может содержать ошибки.
- Качество: пользователь явно выбирает ручной эталон, его ревизию и исходную AI-оценку либо пропуск. MAE, покрытие, метрики критериев и исключённые пары — внутренние метрики команды.
- Расход: весь пакет (включая неудачные вызовы), выбранные оценки либо ID выполнений. Известная стоимость, вызовы, токены и полнота учёта. Неизвестный расход не подменяется нулём, валюты не складываются.
- Два экспорта: архив диалогов/истории и отдельный JSON 1.0 для сдачи. Выбор DEV/PROD, команды, реальных моделей, завершённого пакета или конкретного исхода каждого диалога. Ручные оценки не включаются в сдачу; исходные оценки и официальные правила проверяет сервер.
- Черновики ручной формы и чек-листов, адаптивность, клавиатурная навигация.

## Сохранение и повторы

Перед созданием AI/ручной оценки или пакета `operations.js` сохраняет точные тело запроса и Idempotency-Key в sessionStorage. При потере ответа восстановление использует тот же ключ и тело, в том числе после перезагрузки. После подтверждённого POST читается актуальный результат через GET: повтор POST может вернуть снимок до апелляций. Намеренно новая оценка получает новый ключ; неподтверждённый прежний запрос требует явного решения пользователя.

Клиент ожидает одиночную оценку 185 секунд, больше серверных 180. Отключение браузера не означает отмену модели. X-Execution-ID неудачного вызова сохраняется для отчёта расходов. Браузерные ключи привязаны к выбранному адресу API и текущей вкладке; закрытие вкладки может удалить журнал. Сам список серверных пакетов восстанавливается независимо от браузерного журнала. Старые незавершённые запросы предыдущей версии без ключей не повторяются автоматически.

Черновики содержат поля формы и цитаты, без полного набора и секретов. Привязка — сервер, сущность, версия и fingerprint. Устаревший ручной черновик не отправляется поверх изменившихся данных; чек-лист можно открыть отдельной копией. При недоступном хранилище ключ запросу не теряется молча: отправка блокируется с объяснением.

## Сдача результатов

В разделе «Сдача результатов» выберите набор и DEV (65 диалогов) либо PROD (10 чатов). Заполните фактическое имя команды, режим и названия моделей. Выберите пакет на весь набор или явно выберите исходную AI-оценку/ошибку для каждого внешнего ID. Кнопка скачивает точный ответ backend как `results.json`.

Команда отдельно добавляет файл в `results/dev/results.json` или `results/prod/results.json`, делает commit и push. Интерфейс и сервер Git не обновляют. Архивная выгрузка со страницы диалогов не заменяет файл сдачи.

## Проверка

```powershell
cd frontend
npm run check
npm test
python -m unittest discover -s tests -p "test_*.py"
```

На новом backend 695ab11 с отдельной SQLite-базой и явно искусственным evaluator проверены: серверный пакет с частичной ошибкой, отмена только ожидающих, восстановление после перезагрузки, прекращение опроса, потеря принятого POST и повтор с прежним ключом без дубликатов. Такая же потеря ответа проверена для одиночной и ручной оценки.

Проверены отчёт качества с конкретной ревизией/AI и явным пропуском, расход с неудачным вызовом и неизвестными данными, выгрузка DEV 65 результатов с одной ошибкой через пакет и явный список, мобильная ширина 375 px без переполнения. Автоматические тесты покрывают восстановление, гонки опроса/отмены, привязку к серверу, неизвестный расход, точность денежного представления, состав сдачи и прежние фильтры/черновики.

Размещённый backend проверен через локальный сервер чтением health и списка наборов. Реальная модель на нём пока не подключена (`ai_configured=false`): интерфейс сохраняет ручную проверку, не имитирует AI. Реальный платный вызов и итоговая точность модели этим прогоном не проверены. QA-сервер, база и искусственные результаты находятся вне приложения и в архив не входят.

## Файлы

- `serve.py` — локальный запуск и фиксированная передача API-запросов.
- `app.js`, `api.js`, `operations.js` — навигация, подключение и сохранённые операции.
- `dialogs.js`, `dialogs-model.js` — список, фильтры, сортировка и выбор.
- `batch.js` — создание, список и наблюдение серверных пакетов.
- `reports.js`, `submission.js` — отчёты и отдельная сдача JSON.
- `review.js`, `checklists.js`, `drafts.js` — оценки, правила, апелляции и черновики.
- `ui.js`, CSS — общие элементы и оформление; `tests/` — проверки.

## Улучшения интерфейса — 7 ноября 2026

Мобильная навигация сворачивается в «Разделы» и управляется Enter/Escape. В списке диалогов основные фильтры видны сразу, дополнительные раскрываются на узком экране; выбранные значения остаются в подписи. Действия пакетной проверки появляются после выбора диалогов. На широком экране все пять фильтров стоят в одном ряду.

В карточке оценки появился возврат от сообщения к критерию. Длинные названия критериев переносятся, статус на телефоне стоит отдельной строкой. Ручная форма раскрывает нужный критерий и переводит фокус в первое незаполненное поле. Переключение N/A в редакторе не теряет фокус, подсказки связаны с полями.

Отчёт качества разделён на выбор и сравнение; полные сведения о выбранной оценке доступны под полем. Сдача результатов показывает следующий необходимый шаг и переводит фокус к ошибке. Обновление списка и карточки пакета можно приостановить: сервер продолжает работу. Неизменившиеся ответы опроса больше не пересоздают таблицу.

Ошибки остаются до закрытия. Успешное уведомление задерживается при наведении или фокусе. Границы полей усилены до контраста 3,34:1 на белом; мобильные поля имеют текст не меньше 16 px. Сохранены светлая панель, зелёные акценты и поддержка уменьшенного движения.

Проверка: 36 тестов Node проходят, синтаксис 12 модулей проверен. В Chromium проверены клавиатура, ширины 320/375/1200/1440 px, увеличение корневого размера текста до 200% в списке, оценке и редакторе, формы отчётов и выгрузка искусственного DEV-набора. Пауза наблюдения проверена отдельно от отмены серверного пакета. Это не полный аудит WCAG: экранный диктор, Safari/Firefox и реальные мобильные устройства не проверялись.

## Ожидание лимита и продолжение пакета

В карточке пакета отдельно показаны ожидание лимита, ожидание квоты, ошибка и
отмена до запуска. При наличии серверных полей отображаются время следующей
попытки (по часам устройства) и число повторов. Ожидающие элементы продолжает
сервер; «Приостановить обновление» останавливает только опрос страницы.

После исчерпания автоматических повторов кнопка «Продолжить пакет» отправляет
POST в `/api/v1/evaluation-batches/{id}/resume` без тела. Она доступна для
failed-элементов с AI_RATE_LIMITED/AI_QUOTA_EXHAUSTED и без evaluation_id,
в том числе пока другие элементы ещё выполняются. Готовые результаты, отменённые
элементы и остальные ошибки сохраняются. Серверный cooldown не снимается.
Двойной клик блокируется; после потери ответа UI перечитывает GET и никогда
автоматически не повторяет POST. Если GET тоже не удался, сначала нужно обновить
состояние. Новый пакет при продолжении не создаётся.

Одиночная оценка сохраняет Retry-After вместе с прежними телом и Idempotency-Key.
Время ожидания переживает перезагрузку и ответ 409 на проверку исходного запроса.
История и отчёт расхода доступны во время паузы; новая оценка возможна после неё
только по явному действию пользователя. Истечение таймера не вызывает модель.

Для локального backend запускайте из корня репозитория:

```powershell
python frontend/serve.py --api http://127.0.0.1:8000
```

Без `--api` используется общий сервер команды; push в Git не обновляет его
автоматически.

## Ограничения

Баллы вычисляет backend; UI не дублирует формулу. Ручная форма вводит одну цитату на критерий, отображение модели поддерживает все цитаты. Аудио по ссылке не синхронизировано с таймкодами цитат. Сводки и выбор оценок используют существующий экспорт набора; для больших историй отдельный endpoint был бы эффективнее.

Учебный `demo-dataset.json` содержит искусственные диалоги, не Ground Truth. Реального DEV-набора, оценок, тарифов, базы и ключей в frontend нет. Автор/ревьюер — подписи по контракту backend; frontend не добавляет систему аккаунтов.

## Обновление оформления — Unslop

Направление согласовано: светлая навигация, нейтральные поверхности, зелёный только в действиях, выборе и доказательствах. Название продукта — Replimetr; функции сохранены.

Продукт: рабочее место эксперта по проверке диалогов. Характер: спокойный, точный, деловой. Среда: журнал проверок. Главные акценты: итог и подтверждающая цитата. Характерная деталь: ID сообщения связывает критерий с исходной перепиской.

Исходный аудит: крупная зелёная навигация и плашки; капс с разрядкой; декоративные иконки статистики; повторяющиеся подписи; рекламные слоганы; избыточные зелёные поверхности; разнородные отступы и размеры метаданных; отдельная карточка почти для каждого элемента.

Изменения по проходам:

1. Отступы: ритм 4 px, навигация 36 px, боковая панель 240 px, одинаковые интервалы внутри групп.
2. Цвет: белые и серые поверхности, три роли текста; существующий зелёный оставлен акцентом. Ошибки и предупреждения сохраняют смысловые цвета.
3. Иконки: единый штрих 1.5 и размер 18 px; декоративные иконки счётчиков удалены.
4. Тексты: конкретные названия задач вместо слоганов, сокращённые подписи; пустая оценка больше не утверждает, что модель обязательно отключена.
5. Типографика: Segoe UI для интерфейса, Consolas для ID и чисел; веса 400–600, табличные цифры, без капса и разрядки в подписях.
6. Компоновка: сохранён порядок разделов; статистика компактнее, редактор правил организован как реестр, транскрипт — как журнал реплик.
7. Детали: тонкие разделители, спокойные статусы, единые состояния фокуса; ID сообщений и значимые пометки ручной оценки/N/A не скрыты.
8. Визуальная часть: содержание диалога и его доказательства вместо декоративных изображений. Генерация изображений не использовалась, промптов нет.
9. Движение: только короткая обратная связь для элементов и индикаторы реальной загрузки; поддержка reduced motion сохранена.

Проверка после изменения: синтаксис всех JS-модулей; сравнение API и функциональных DOM-атрибутов с исходниками; открытие оценки на отдельной учебной базе, переход от цитаты к реплике, ручная форма с девятью критериями, редактор правил. При ширине содержимого 375 px у страницы и диалога нет горизонтального переполнения. Бэкенд, формула балла, пользовательские диалоги, правила и данные не менялись.
