# Ketnavr — frontend

Готовый интерфейс на HTML, CSS и JavaScript для backend из `data_ch-codex-backend-core.zip`. Сборка и npm-зависимости не нужны. Скопируйте папку `frontend` в корень командного репозитория, рядом с `backend`, `docs` и `pyproject.toml`.

## Запуск

Сначала запустите backend по его README на `http://127.0.0.1:8000`. Если он ещё не установлен, выполните **из корня репозитория** в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]" -c requirements-lock.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --env-file .env --host 127.0.0.1 --port 8000
```

Если `.env` уже существует, сохраните его настройки и пропустите `Copy-Item`.

Во втором терминале **из корня репозитория**:

```powershell
python -m http.server 5173 --bind 127.0.0.1 --directory frontend
```

Откройте **http://127.0.0.1:5173**. Не открывайте `index.html` двойным щелчком: ES-модулям нужен HTTP-сервер. Остановить каждый сервер — `Ctrl+C` в его терминале. На macOS/Linux при необходимости замените `python` на `python3`; backend запускается через `.venv/bin/python`.

Если вы уже находитесь в папке `frontend`, достаточно `python -m http.server 5173 --bind 127.0.0.1` или `npm start`. Node нужен только для необязательной команды `npm run check`.

Адрес backend меняется кнопкой шестерёнки в правом верхнем углу и сохраняется локально в браузере. Для другого компьютера команда должна использовать один общий backend; участник backend добавляет точный адрес frontend в `CQA_CORS_ORIGINS`.

## Что работает

- Импорт JSON в формате backend, массива записей или ответа организаторов `{isSuccess:true,data:{records:[...]}}`; отдельный серверный импорт DEV.
- Несколько наборов, фильтры RU/KZ/EN и чат/звонок, поиск по внешнему ID, страницы по 15 диалогов, последняя оценка.
- Исходный транскрипт с ролями, временем и ID сообщений; для звонков — аудиоплеер, если в записи есть ссылка.
- Выбор чек-листа и версии, запуск AI, состояния загрузки и понятные ошибки `AI_NOT_CONFIGURED` и других ошибок API.
- Ручная оценка всех критериев, числовые шкалы, N/A, пояснения, точные цитаты и отметки дополнительной проверки.
- История, снимок правил и диалога, исходный и текущий балл, отдельные флаги нарушений, переход от цитаты к сообщению с подсветкой.
- Редактор произвольных чек-листов: создание, копирование, новые критерии, бинарные ответы/шкалы/флаги, правила для звонков, веса и N/A. Каждое сохранение создаёт версию.
- Апелляция по критерию, очередь в выбранном наборе, решение с цитатой, защита конфликтов версий и пересчёт на backend.
- JSON-экспорт диалогов, оценок и апелляций.
- Адаптивная вёрстка, клавиатурная навигация, защита открытых черновиков от случайного закрытия.

В пустой базе кнопка «Открыть пример» загружает четыре **искусственных** диалога из `demo-dataset.json`. Это только данные для интерфейса, не Ground Truth. Сохранённых оценок, реального DEV-набора и секретов в frontend нет.

## Границы

AI по-прежнему подключается участником модели на backend. Ручные оценки явно помечены; интерфейс не имитирует AI. Импорт организаторов требует `CQA_ORGANIZER_API_URL` только на сервере. При отсутствии этой настройки доступен файловый импорт.

Формула оценивания здесь не дублируется: UI отображает `score` и `original_score` сервера. После апелляции исходный результат сохраняется. Архивные версии правил не редактируются.

Оценки запускаются по одному диалогу; фоновой очереди и пакетной проверки в этой версии нет. После сетевой ошибки сохранения проверьте историю перед повторным запросом. Черновики находятся в памяти страницы и не сохраняются после принудительной перезагрузки.

Ручная форма принимает одну цитату на критерий. При отображении ответа модели поддерживаются все переданные цитаты. Аудио доступно только по ссылке, без автоматического сопоставления фрагментов с таймкодами. Встроенный браузерный плеер может зависеть от доступности и формата аудиофайла.

Для очереди апелляций используется один JSON-экспорт выбранного набора: отдельного эндпоинта списка апелляций в backend нет. Оценки списка загружаются только для видимых строк, максимум три параллельных запроса.

Автор и ревьюер — подписи, как в текущем backend, без учётных записей. Этот вариант предназначен для локального командного демо.

## Файлы

- `app.js` — навигация, диалоги, импорт/экспорт, очередь апелляций, адрес API.
- `api.js` — запросы и обработка ошибок.
- `review.js` — транскрипт, ручная/AI-оценка, история, цитаты, решения.
- `checklists.js` — редактор правил и версий.
- `ui.js` — экранирование текста, иконки, диалоги, уведомления.
- `style.css`, `review.css`, `checklists.css` — оформление и адаптивность.

## Проверка

Проверено в браузере на поставленном backend: импорт JSON и учебного набора, языковые фильтры, ответ AI503, ручная оценка восьми критериев с N/A и числовой шкалой, апелляция, пересчёт 87,5 → 93,75 с сохранением исходной оценки, очередь, скачивание экспорта. Создана версия v2 с девятым критерием; он появился в ручной форме, v1 осталась архивной. Эти изменения выполнены только в отдельной тестовой базе и в архив не включены.

На узком экране проверены список и экран диалога: страница не выходит за ширину; таблица прокручивается внутри своего блока. Синтаксическая проверка модулей: `npm run check`. Реальный AI, сервер организаторов и воспроизведение удалённого аудио без предоставленной записи не проверялись.

## Обновление оформления — Unslop

Направление согласовано: светлая навигация, нейтральные поверхности, зелёный только в действиях, выборе и доказательствах. Название продукта — Ketnavr; функции сохранены.

Продукт: рабочее место эксперта по проверке диалогов. Характер: спокойный, точный, деловой. Среда: журнал проверок. Главные акценты: итог и подтверждающая цитата. Характерная деталь: ID сообщения связывает критерий с исходной перепиской.

Исходный аудит: крупная зелёная навигация и плашки; капс с разрядкой; декоративные иконки статистики; повторяющиеся подписи; рекламные слоганы; избыточные зелёные поверхности; разнородные отступы и размеры метаданных; отдельная карточка почти для каждого элемента.

Изменения по проходам:

1. Отступы: ритм 4 px, навигация 36 px, боковая панель 240 px, одинаковые интервалы внутри групп.
2. Цвет: белые и серые поверхности, три роли текста; существующий зелёный оставлен акцентом. Ошибки и предупреждения сохраняют смысловые цвета.
3. Иконки: единый штрих 1.5 и размер 18 px; декоративные иконки счётчиков удалены.
4. Тексты: конкретные названия задач вместо слоганов, сокращённые подписи; пустая оценка больше не утверждает, что модель обязательно отключена.
5. Типографика: Segoe UI для интерфейса, Consolas для ID и чисел; веса 400–600, табличные цифры, без капса и разрядки в подписях.
6. Компоновка: сохранён порядок разделов; статистика компактнее, редактор правил организован как реестр, транскрипт — как журнал реплик.
7. Детали: тонкие разделители, спокойные статусы, единые состояния фокуса; ID сообщений и значимые пометки ручной оценки/N/A не скрыты.
8. Визуальная часть: содержание диалога и его доказательства вместо декоративных изображений. Генерация изображений не использовалась, промптов нет.
9. Движение: только короткая обратная связь для элементов и индикаторы реальной загрузки; поддержка reduced motion сохранена.

Проверка после изменения: синтаксис всех JS-модулей; сравнение API и функциональных DOM-атрибутов с исходниками; открытие оценки на отдельной учебной базе, переход от цитаты к реплике, ручная форма с девятью критериями, редактор правил. При ширине содержимого 375 px у страницы и диалога нет горизонтального переполнения. Бэкенд, формула балла, пользовательские диалоги, правила и данные не менялись.
